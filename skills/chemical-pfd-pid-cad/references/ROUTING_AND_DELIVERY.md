# 排线、标注与同版交付

适用：把已核流程或首版CAD的布局落实为真实接线，修改显示流股/字段，或准备DWG/PDF及配套表。此页整理实际空分案例的漏检机制；它不是国标条文，也不提供通用化工设计。国赛原图管表达参考，采用标准管本图要求，项目来源管本案拓扑与数据。

## 先形成能检查的输入

- 冻结对象及服务、完整图例来源、逐口连接、允许位置变换、流股/管线ID与准确字段。图例和全部端口、向外法向、接管直段同变换；不能按图片像素或外包框猜真实接点。
- 保存完整来源台账和单独的显示排除清单。排除必须有具体理由与采用授权；不因零流、缺值或图面拥挤自动删项。来源台账保持原数，参数旗、图内表、CSV和读图说明共同消费同一显示集合，不各存一个“当前股数”。字段和单位依本案确定，案例中的旗数、F/T/P/VF排列、字体校准系数不成为通用常量。
- 实际看同用途国赛整图、标记局部及完整图例，再用自然语言写清：哪条流股挂哪种旗，字段顺序与单位，箭头和引线归属，图内表怎样同号关联。实际图册附给Image，不以“已经检索”替代附件。
- 在定线前提供全部应显示旗、文字、引线、仪表和箭头的区域/身份。初稿用保守范围预留空间，终验用同版原生文字包络和实际PDF；仅设备避障通过不能叫整图无碰撞。

## 给Image的排线说明

正常按当前车间或明确工艺范围画流程，主线、支线和真实回流易于追踪。自由决定设备位置与留白，不规定蛇形行列；空间不足扩大画布或按真实接口分块，不能缩字塞满单框。

每条已知连接从真实接管沿其向外轴离开，到目标时沿目标向外轴的反向接入。接管附近留直段，不能沿设备壁重叠，也不能穿设备。支路/汇流只在连接合同指定的位置形成明确T接或所选案例的接点表达；两个线段坐标相交不代表相连。

先通过布局减少交叉和共线重叠。工程图中确需非连接交叉时，按本项目采用约定建议连续拱桥；被跨线保持连续，不画断口，也不把桥画成分支。图例内部线保持原貌，过程接管短线与对应主管等宽。Aspen仅布局按调用方原生表达，不为套桥改造原生图标。

留出实际参数旗、编号、单位、图内关联表、仪表和箭头的位置，连接线不穿标记，箭头不盖文字。不能添加无依据设备、喷嘴、分支或参数。Image不负责准确字体和数据；CAD必须从冻结资料写入。二次Image只优化已经制作并按需合并的CAD的相对位置、走线与留白，仍用原图元、字段和字体重画。

上述意图已进入请求准备器的固定提示。图片只提供候选；桥的连续性、文字字形和标准适用性必须在实际CAD中验证，不能由提示词自证。

## CAD排线与连接算法的实际边界

1. **先核端口，再找路径**：源端向外离开，目标沿其向外向量的反向到达。变换后重新核法向与最小直段；首末短段和所属设备内部区域都检查，不豁免整台设备。
2. **将Image通道转成少量已审必经点**：在明确坐标/比例下把确需保留的通道用 `connections[].checkpoints` 表达，按源到目标顺序。点须有限、唯一，并且不免除避障。不要逐像素塞点或用点列固化蛇形；设备/标注布局改变后重新核点。当前接口是精确必经点，不声称支持任意通道多边形。
3. **受约束候选**：独立libavoid适配器接收端口和必经点；设备和已接纳管线为硬障碍。有界改变排线顺序，无可验路线就返回失败，不能静默丢点、改拓扑、减小间距或删流股。目标方向传给libavoid的是端口向外可见方向，不再次反号。
4. **先验再提交，简化也重验**：独立guard核完整折线、指定必经点的顺序、首末方向、穿体、重入、共线重叠、自交和间距。局部直线/一弯替换只有通过同一守卫才接受；可删共线顶点，但不能绕过必经点。它是局部去冗余，不是全局最优证明。
5. **桥、T接和注释另有职责**：通用router不自动接T、共用端口或产生桥，也未自动把任意文字/旗标清单变成障碍。调用方须提供完整标注上下文，另核路线与实际文字/旗标/引线，并按明确跨越合同使用受支持的桥图元。需要这些对象时不能只运行router就宣布通过。桥全弧、两侧接点、等宽、被跨线连续及误接分别查；桥顶碰字不能靠只测弦漏掉。
6. **箭头后置但不盖字**：基于最终路线放置；核流股归属、尖端方向、与标注的距离，再按真实实体身份置顶。图层名称不等于绘制顺序。无合法位置时反馈布局，不缩字或穿线。

接口和支持范围分别见[几何工具](../tools/geometry/README.md)、[交付清单工具](../tools/delivery/README.md)。已登记障碍与“全图内容都已登记”是两项检查。

## 同版数据与实际文件交付

1. 用独立来源冻结准确显示字符串及单位和来源定位。先调用交付清单工具 `prepare`，产生同一显示集合的CAD数据输入、CSV和简洁读图说明；CAD构建器必须实际消费它。字段落图位置和原生文本句柄仍由构建/回读方提供，生成JSON不代表标注已画。
2. 每次修订使用新的运行目录。原DXF、语义、保存关闭重开后的DWG、原生PDF、回读DXF、导出记录、全量文字/流股观测和审核报告绑同版文件哈希；旧报告不借相似文件名复用。图与metadata同时改错时，还必须对照独立来源清单，不能只比较两份副本相等。
3. 核每条应显示流股的实际字段、单位及所属文本句柄；少项、多项、重复、值不同、缺少标注上下文或伪造完成状态均阻断。审核分别覆盖数据、几何、字体和实际原生图面，工具只核记录与内容对账；真实字形/入框/读图性仍由同版原生观察证明。
4. 导出返回码、导出审计和精确输出身份必须同时成功。包装入口使用 `return driver.main(...)` 与 `raise SystemExit(main())` 传播返回码；不能忽略失败后继续复制旧产物。模块导入不得写校准或图纸；项目根、字体配置、图幅、显示集合、打印策略从显式输入传入。复用画布/字体工具不导入退役路由器或旧候选。
5. 本用户任务要求无查看器弹窗时，采用独立任务PC3并在实际导出入口核查相应查看器选项、设备、媒体、比例和线宽。选项/版本无法核实则不宣称无弹窗保证；不要复用个案二进制偏移、修改用户原PC3或结束其他会话。`REPORTERROR=0`只管错误报告，不禁止PDF查看器。
6. 交付前运行 `audit`；失败保持诊断，不作为成品发布。该工具不会打开DWG或替代观测提取器，不核准工程设计，也不自动上传。完整PFD/PID仍须第三关验收；Aspen仅布局前段不被本页扩成CAD交付任务。

## 从本次总结保留什么

采用机制：完整图例真实输入、标注参与布局、少量已审必经点、独立来源与显示集合分开、原生全量文字对账、同版发布、失败状态传播。原案例脚本只是研究快照；本项目没有把它们整体改成可搬迁的通用CAD/PDF生成器。

仍需真实任务验证：自动全量注释障碍接入、任意T接/跨越拓扑、跨字体校准、通用原生导出与无弹窗打印、陌生案例成图。离线工具通过不提升这些状态，也不抹去案例未执行的二次Image环节。
