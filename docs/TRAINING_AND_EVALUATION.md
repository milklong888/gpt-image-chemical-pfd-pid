# 工作流优化、训练示例与评估

> 验证边界：大型案例的历史成果是分图集，完整跨块管线合并与该案例配套 PID 尚在修正。分图原生检查通过不等于整图已交付。

本项目没有重新训练基础模型权重，也不提供微调后的模型检查点。“训练”在这里指三件需分别记录的工作：用任务反馈改进 Skill/检索/执行检查；用新上下文评估规划行为；用明确标记的合成数字测试图面表达。修改提示词、索引和检测代码不能称为模型权重训练。

## 先冻结要验证的主张

一次评估记录图种、任务阶段、来源身份、模型及推理配置、Skill/代码版本、知识generation、输入和验收范围。把以下能力分开：是否主动查资料、是否找对来源、是否理解流程/控制、是否保留已有字段、是否生成正确文件、实际图面是否可读。不能用一次检索成功替代后面各项。

新题答题者只接收正常任务、可用技能与授权资料；审阅者另读原件并建立独立预期。答题过程保存真实调用和阅读记录。私有评分锚点或上题答案不能进入答题提示。需查看历史工具用法或来源发生变化时如实标记程序局限，不宣称完美盲测。

固定观察维度为：实际检索、发现对象后追加模块、来源字段保留、具体流程/控制理解、适用性判断、后续执行交接。任务不适用与缺陷分开。原答、原分数、失败和修正副本分别保存；修正副本通过是同题回归，不是新题泛化成功。不同批的来源、模型配置或推理强度改变时，不把分差单独归因于工作流。

## 从具体失败到最小改进

1. 对照原件定位失败字段、关系或实际图元，先区分检索缺口、理解错误、合同遗漏、实现错误与可读性问题。
2. 查现有责任位置及消费者；优先修一处可干预机制，不为迎合某个模型堆叠重复检查清单。
3. 改进限定为通用触发、来源导航、结构合同或可求值检查。上一题正确数值、设备配对和私有答案留在项目记录，不写成下一题默认。
4. 在原失败副本上回归，并检查相邻反例和未受影响行为。新来源/新任务才用于检查迁移能力。
5. 保留残余限制与必要独立复核。轻量模型仍会错读主线顺序或延期已有内容时，不因修正稿通过而批准其自主冻结设计。

重复出现同类失败时先诊断失效环节；改动后的代码或说明不是修复原因的充分证据。需用实际输入、独立预期和实际返回证明改变作用。

## 故障注入必须作用到文件

先确认合法正例能通过，再从受保护副本注入单个明确故障并保存真实文件。报告目标检测器、实际输出、控制样例和失败位置；故障被另一个前置门提前拒绝，不能冒称目标检测器已被验证。

| 层次 | 可注入的故障 | 需要观察 |
| --- | --- | --- |
| 来源/检索 | 错版本、过期包、载荷变化、漏父条款或例外 | 身份/失效检测与实际内容复核各自是否生效 |
| 数据 | 错T/P/F、单位错借、两端同错、S改R、缺失相态伪装已知 | 从独立来源重算，而非读builder的expected字段 |
| 拓扑 | 漏源符号、反向箭头、跨端误指、漏/重复跨块边 | 实际源图元、方向和两端身份是否被核到 |
| 几何 | 穿设备、短管脱离、重复线、断桥、错半径/端点、伪节点 | 全长及首末段、连续/切向、等宽、非连接语义和空间障碍 |
| 绘制/出图 | 箭头压到线后、非箭头顺序被改、关闭打印排序、字体缺失 | 实际绘制顺序、原生回读和原生PDF是否一致 |

合成小样验证检测器行为，不能充当真实工程任务经验。历史本地大流程故障证明的是其已测范围，未覆盖的新设备、新控制结构和新CAD版本须另验。视觉失败也保留：几何连续但打印小桥近似凸点的候选曾被否决，说明几何通过不能替代可读性判断。

## 训练数字如何使用

仅在用户授权时另建训练场景。原文值原样保留；推导值带输入、公式/规则、单位和假设；合成值逐字段标S并在图签一次说明；缺项保持missing。表格、跨页端点和真实CAD回读使用同一状态与场景版本。用户授权数字不授权改造来源拓扑，也不把合成数据变成热物料衡算、控制设定或工程采用依据。

公开示例应使用自行构造且可授权的拓扑、字体和数字，不附私有题目、原图库或未经许可的标准长段。示例须能故意失败并说明限制，不能只包含美观的正例截图。

## 停止与经验整理

是否继续对抗验证由当前用户范围决定，不靠固定轮数宣布能力已稳定，也不为旧平台条件无限追加。C12完成已发现问题修正回检后，按用户要求收束弱模型压力测试；保留两份原答各8/12，未追加C13/C14演员，不称平台期或统计收敛。减少弱模型题量不取消独立原件复核和真实CAD硬检查。未来重新授权的测试可在新范围内开展。

任务审计与正式经验晋升分开。当前任务允许持续修复；通用经验整理由用户明确发起，相关版本关闭与技术资格满足后再审。候选分为宏观行事原则和数据/方法规律，选择不改、合并、专门化、替换、新增或撤回，写明唯一责任位置、适用域、反例、影响与回退。

局部放宽验收的案例及派生链保留在项目审计，不进入默认规则、默认RAG或通用成功经验。用户直接修订工作流属于显式维护；仍须验证，不借此声称新增工程能力。没有技术增量就保持不改，不以文件数量或题量衡量进化。

## 三类结果分别报告

| 结果 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 公开代码/合成夹具测试 | 该发行代码在给定依赖和样例上的行为 | 私有案例完整性、真实CAD或工程核准 |
| 历史本地原生CAD验证 | 指定案例、版本、文件及环境的真实运行与回读 | 公开包已能复现、任意P&ID生成能力 |
| 公开可复现实验 | 他人可取得合法输入、依赖、命令和可核预期并重跑的范围 | 未公开数据/专有软件环境下的全部能力 |

当前公开复现情况必须跟发行文件和实际运行记录更新，不从历史成功自动继承，详见[验证状态](VALIDATION_STATUS.md)。
